NOT A DIAGRAM

Known gaps

The schema itself is fully valid (prisma validate passes with zero errors across all 46 models). What's left below is missing application/API code, not missing data model — openspec/changes/add-cart-wishlist-store-config was schema-only by design.

Cart, Wishlist & Store Settings have no API routes yet

Cart/CartItem/Wishlist/WishlistItem/StoreSetting exist in the schema (see Cart & Wishlist and Store Settings sections) but src/app/routes/index.ts only mounts /auth and /users — no controllers/services/routes consume these models yet. Guest-cart cookie handling and the login-time cart-merge logic are also not implemented.

CartItem uniqueness gap for simple products

PostgreSQL treats NULL as distinct from NULL in unique constraints, so CartItem's @@unique([cartId, productId, variantId]) doesn't fully dedupe two rows for the same non-variant product (both variantId = null). Must be enforced at the application layer (find-or-increment) once the cart API is built.

Tax / currency are flat by design, not a gap to fill later

StoreSetting.defaultTaxRatePercent is one flat rate and currency is a single active currency — deliberate scope decisions (see design.md in add-cart-wishlist-store-config), not oversights. A per-region tax engine or multi-currency support would be a separate future change.

Product categorization: primary + additive, not fully unified

Product.categoryId (primary/canonical) and the new ProductCategory join table (supplementary tags) are two separate mechanisms living side by side by design — see the Catalog section. Not a bug, just worth knowing when querying "all categories for a product."
